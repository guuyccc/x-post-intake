# 录入标准（与现有 48 个 case 严格一致）

本文件是分类、文案、格式的唯一标准。录入新帖子时必须逐条对照。

## 一、单元格 XML 模板

```xml
<td vertical-align="top"><p><b>{标题}</b>｜<a href="{帖子URL}">@{handle} 原帖</a></p><img src="{封面token}" width="280" height="{按比例高度}" name="opus55_{英文小名}.jpg"/><blockquote><p>{一句话概括}</p></blockquote><p><span text-color="gray">▶️ {Views} Views · ❤️ {Likes 千分位} Likes</span></p></td>
```

**「三方软件接入」类的单元格**在标题行与封面之间额外加一行工具标签（每个工具一个 `<code>`）：

```xml
<p><b>{标题}</b>｜<a href="{帖子URL}">@{handle} 原帖</a></p><p><code>Blender</code> <code>Unity</code></p><img .../>
```

工具名从帖子正文/视频里确认（如 `Blender`、`Unity`、`Unreal Engine`、`WoW`、`three.js`、`Blender MCP`、`GPT`），有几个写几个；只有「三方软件接入」大类加这行，其他类不加。

- 图片宽固定 280，高按封面宽高比换算（封面抽帧/海报通常为 560 宽，高减半即可）。
- `▶️` `·` `❤️` 与空格格式照抄模板；Views 用 X 显示原值（如 `1.5M`、`690.5K`、`5,850`）；Likes 用千分位数字。
- XML 文本里 `&` `<` `>` 要转义；英文评价原文直接放「」里，不用转义引号。

## 二、标题写法

- 4~14 字中文短语，说清「做了什么」，动词开头优先；保留关键专名（游戏名、软件名、地名）。
- 现有示例：`可拆解的火箭发动机`、`斯普拉遁复刻`、`边玩 WoW 边 vibe coding`、`$2,175 tokens 烧出的在线游戏`、`7500 行代码像素级仿名画`、`iPhone Duo 变 Nintendo DS`。
- 不要写成评价句（如「太强了」），不要带句号。

## 三、一句话概括写法

结构：**做了什么（1 句）+ 作者评价原话（「」引用）**。

- 概括部分：说明 case 的内容与实现方式（纯代码 / three.js / Blender / Unity / UE / 接了什么数据）。
- 评价部分：从帖子文案里挑最有信息量的原文短语放「」里，如「HOLY fuck, everything you see AND hear is code」「This is INSANE 🫣」；没有明显评价词时可只写事实（如「Opus 5.5 复刻 Splatoon，附实机演示视频与可玩链接」）。
- 1~2 句，不超 60 字（不含引用）。
- 现有示例：
  - 「让 Opus 5.5 造一台浏览器里可拆开的 Raptor 3 来讲原理：剖开箭体、跟着液氧甲烷流过两级涡轮泵再点火。」
  - 「Opus 5.5 ultracode 复刻儿时 PS2 梦想游戏《Dynasty Warriors》：赵云战 300 兵，连招、闪避、无双俱全，「ultracode is unreal」。」

## 四、分类标准（5 大类 + 子标签）

### 1. 代码动画
不接任何外部资产、纯 JS/Python 等代码逐帧生成的**艺术向**动画/画作/音乐/视觉作品。

| 子标签 | 定义 | 现有成员 |
|---|---|---|
| 叙事短片 | 有故事线、角色或概念表达的动画短片 | 各模型厂一镜到底、儿童绘本风动画、用 JS 画出自己的一生、想象自己的 TikTok 信息流、想象自己解难题、Claude 模型发展史动画、small print |
| 风格实验 | 玩视觉风格/画种/像素/材质风格，含游戏 UI 美术 | 7500 行代码仿名画、像素巫师、像素夜城+lofi、游戏结算/抽卡动画、旅行相册、任意风格交互视频 |

### 2. 动效动画
产品发布/品牌宣发向的 motion design（launch video、宣发片、名称/logo/UI 动效）。子标签唯一：**产品宣发**。
现有成员：15 分钟出宣发片、一句提示词出完整宣发片、Ultracode 12 小时动态设计。

### 3. 3D 场景与交互
浏览器/网页端（three.js、WebGL 等）的 3D 场景、交互体验、仿真，以及**纯网页实现的游戏**。

| 子标签 | 定义 | 现有成员 |
|---|---|---|
| 游戏 | 纯网页（非 Unity/UE 引擎）做出的可玩游戏 | 斯普拉遁、马里奥赛车、Dark Souls、多人割草、海岛 FPS、开放世界 NYC、真三国无双 |
| 场景 | 3D 场景、装置、概念设计、场景复刻 | 沙虫机器人、鹈鹕骑车、折叠公路、Luna 3D、可爱世界、金门大桥 |
| 仿真 | 物理/材质/光学/机械/设备仿真与可交互拆解 | 火箭发动机、镜头对焦实验室、iPhone Duo 变 DS、果冻、草地树木、毛发 |

### 4. 三方软件接入
调用了第三方专业软件或平台完成的 case（Blender、Unity、UE、WoW 插件、MCP 等）。

| 子标签 | 定义 | 现有成员 |
|---|---|---|
| 游戏 | 用引擎/平台做的游戏及游戏内工具 | $2,175 网游、WoW 插件、毒液蜘蛛侠、Unity 钓鱼、UE 旧金山、t31kx 一条提示出游戏 |
| 其他 | 建模、动画、仿真、横测等非游戏 | 草图仿真、黏土动画、Stefan 横测、发丝级建模 |

### 5. 真实世界交互
与真实世界的物品、空间、教程、图纸交互的 case（园艺、桑拿房、健身房、CAD、房屋建模）。**即便接入了 Blender 等三方软件也归这里。**

| 子标签 | 定义 | 现有成员 |
|---|---|---|
| 真实建模 | 把真实空间/物品/教程做成可交互 3D | 园艺 3D 手册、健身房搭建、桑拿房教程 Skill |
| 物理操控 | 操控真实硬件/设备（暂无成员，预留） | — |

## 五、边界裁决规则（判不准时按此执行）

1. **横测/对比不单独成类**：Opus vs Astra/Luna 等对比帖，按其内容形态归类（3D 渲染对比→3D 场景与交互/仿真；Blender 对比→三方软件接入/其他）。
2. **游戏二分**：纯网页技术（JS/three.js）→ `3D 场景与交互/游戏`；游戏引擎或平台（Unity/UE/Blender/WoW）→ `三方软件接入/游戏`。引擎不明时默认定 `3D 场景与交互/游戏`。
3. **真实世界任务优先**：为真实空间/物品/教程服务（而非单纯炫技场景）→ `真实世界交互`，不看是否用了三方软件。
4. **宣发片二分**：讲品牌/产品发布的 motion 片→`动效动画`；艺术表达/叙事/风格向的纯代码片→`代码动画`。
5. **游戏美术 vs 游戏本体**：游戏结算/抽卡/UI 动效→`代码动画/风格实验`；可玩的游戏本体→按第 2 条分。
6. 仍判不准：选最接近的一类，在汇报里说明理由并标注「分类待人工确认」。

## 六、其他一致性要求

- **Likes** 取 syndication API 的 `favorite_count`（抓取当时的值，不回头刷新旧记录）。
- **Views** 取帖子页 analytics 显示值；抓不到填「待补」。
- **封面**：用帖子自带海报帧/图片，280px 宽展示；禁 GIF、禁视频块。
- **查重**：tweet_id 在文档或多维表格任一出现即跳过。
